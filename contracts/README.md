# Бондинг-кривая для токенов Mintly

Контракт-рынок для токена, запущенного в приложении. Одна кривая — один
токен.

## Зачем не обычный AMM

Обычному пулу нужна ликвидность: пока кто-то не внесёт пару TON/токен,
торговать нечем. У свежего мемкоина такой пары нет, поэтому первые
покупатели упираются в пустоту — ровно это и происходит сейчас, токены
минтятся без рынка.

Кривая сама выступает второй стороной сделки. Цена считается формулой, а
не чужими заявками, поэтому купить можно с первой секунды и никому не
нужно рисковать своими деньгами ради запуска.

## Формула

Постоянное произведение на **виртуальных** резервах:

```
k = (virtualTon + realTon) × (virtualTokens − tokensSold)
```

`virtualTon` и `virtualTokens` задают стартовую цену и крутизну роста, но
не лежат на контракте. Реальные деньги — только `realTon`. Благодаря
этому первая покупка не выкупает весь запас за копейки, как было бы на
пустом пуле.

Округление везде в пользу контракта: покупатель получает не больше
расчётного, продавец — не больше расчётного. Иначе цикл «купил-продал»
по копейке выкачивал бы резерв.

## Жизненный цикл

1. Разворачивается жетон (это делает приложение) и сама кривая.
2. Админ один раз присылает `SetJettonWallet` с адресом кошелька жетона,
   принадлежащего кривой. Повторно адрес поменять нельзя.
3. Весь `tokensForSale` минтится на этот кошелёк.
4. Люди покупают: TON приходят с сообщением `Buy`, кривая шлёт жетоны.
5. Люди продают: переводят жетоны на кошелёк кривой, та возвращает TON.
6. Когда `realTon` достигает `graduationTon`, торговля закрывается.
7. `Graduate` переводит собранные TON и непроданный остаток на
   `graduationDestination` — для заведения пары на настоящем DEX.

## Что защищено

- **Деньги нельзя вынуть досрочно.** Единственный вывод — `Graduate`, и
  только после порога, и только на `graduationDestination`, заданный при
  создании. Админ не может ни забрать раньше, ни сменить получателя.
- **Подделка продажи.** Уведомление о переводе жетонов принимается только
  от собственного кошелька кривой — иначе кто угодно прислал бы
  поддельное и выкачал резерв.
- **Проскальзывание.** `minTokensOut` при покупке, `minTonOut` в
  forwardPayload при продаже.
- **Недостижимый порог.** Контракт не развернётся, если `graduationTon`
  выше того, что кривая физически способна собрать при полностью
  распроданном `tokensForSale` — иначе деньги заперлись бы навсегда.
- **Продажа сверх купленного.** Отвергается: `amount ≤ tokensSold`.
- **Разбор forwardPayload не бросает исключений.** Исключение в
  обработчике уведомления означало бы, что жетоны остались на кривой, а
  продавец их потерял. Непонятный payload трактуется как «ограничения
  нет».

## Команды

```bash
npm install
npm run build   # компиляция Tact → build/
npm test        # 12 тестов в песочнице
```

Развёртывание:

```bash
TON_MNEMONIC="..." \
JETTON_MASTER=EQ... \
FEE_WALLET=EQ... \
GRADUATION_DESTINATION=EQ... \
NETWORK=testnet \
npx tsx scripts/deploy.ts
```

## Параметры по умолчанию

| Параметр | Значение | Смысл |
|---|---|---|
| `virtualTon` | 30 TON | стартовая цена и крутизна |
| `virtualTokens` | 1 073 000 000 | то же |
| `tokensForSale` | 900 000 000 | сколько уходит через кривую |
| `graduationTon` | 100 TON | порог выпуска на DEX |
| `feeBps` | 100 (1%) | комиссия платформы с обеих сторон |

При этих числах потолок сбора — около 156 TON, то есть порог в 100
достижим с запасом.

## Чего ещё нет

- **Аудита.** Контракт держит чужие деньги; перед мейннетом он обязан
  пройти внешний аудит. Тесты покрывают логику, но не заменяют его.
- **Связки с приложением.** `src/tonLaunch.js` пока разворачивает жетон
  без рынка, а кнопки «Купить/Продать» шлют только сетевую комиссию.
  Следующий шаг — разворачивать кривую вместе с жетоном, минтить запас на
  её кошелёк и переключить кнопки на `Buy` и перевод жетонов.
- **Автоматического заведения пары на DEX.** `Graduate` отдаёт деньги и
  остаток на заданный адрес; пару там заводит уже внешний код.
- **Индексации сделок.** Лента и график пока читают GeckoTerminal, где
  токенов с кривой нет. Понадобится свой индексатор транзакций кривой.
